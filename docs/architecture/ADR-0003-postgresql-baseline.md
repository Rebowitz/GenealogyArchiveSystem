# ADR-0003: PostgreSQL minimum supported version

- **Status:** Accepted (Phase 0, approved by project owner)
- **Governs:** BUILD-SPEC s.5, s.6, s.65; PHASE-0 "PostgreSQL connectivity ... on Windows and Linux"

## Decision
**PostgreSQL 16 is the minimum supported major version.** CI tests the baseline (16) and the current
major release (18) on both native Windows and Linux runners.

## Rationale
- It is a conservative, currently supported baseline appropriate to a long-lived personal/small-institution
  archive: mature, widely deployed, and supported by the PostgreSQL community through **November 2028**.
- It is the distribution default on **Ubuntu 24.04 LTS** and available through the official installers
  on Windows, so a typical installation needs no third-party repository.
- Nothing required by the Genealogy Archive System needs a newer major version. In particular, UUIDv7
  identifiers (BUILD-SPEC s.8, Phase 1) will be generated by the application rather than by
  PostgreSQL 18's `uuidv7()` function, so the minimum does not rise for that reason.

(14 and 15 are also still community-supported; 16 was chosen for the reasons above, not because it is
the oldest supported version.)

## Enforcement
- `PostgresServer.MINIMUM_MAJOR_VERSION = 16`. The `migrate` command refuses older servers; `status`,
  readiness and the worker report them as unsupported.
- Raising the baseline requires a concrete Genealogy Archive System requirement, an updated ADR and CI
  matrix, and must be planned before November 2028.
- Migrations should avoid features newer than the baseline. A migration that needs a newer feature must
  first raise the baseline through this ADR.
